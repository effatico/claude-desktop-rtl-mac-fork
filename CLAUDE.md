# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A macOS-specific patcher that makes Persian text (mixed with English) render correctly in Claude Desktop. It does **not** modify the original `/Applications/Claude.app` — it produces a separate patched copy at `~/Applications/Claude-RTL.app`.

This repo (`effatico/claude-desktop-rtl-mac`) is a fork of [soguy/claude-desktop-rtl-mac](https://github.com/soguy/claude-desktop-rtl-mac), specialised for Persian. The macOS patching pipeline came from that project; the RTL JS (`rtl-payload.js`) started from the Windows project [shraga100/claude-desktop-rtl-patch](https://github.com/shraga100/claude-desktop-rtl-patch) and has since been rewritten around a dominant-language rule.

**Persian first.** The main use is Persian mixed with English, mostly in the Code tab. Defaults, examples and docs are Persian: Vazirmatn is the default font, and a change is checked with Persian + English text. The code still handles every RTL script (the detection range and the font `unicode-range` cover Arabic and Hebrew); do not remove that, and do not let it drive design decisions either. [README.md](README.md) is Persian on top (inside `<div dir="rtl">`, closed around each code block so code stays LTR) with the full English version below; keep the two halves in step when either changes.

## Commands

```bash
./patch.sh --install     # Build patched copy at ~/Applications/Claude-RTL.app and launch it
./patch.sh --uninstall   # Delete the patched copy (original is never touched)
./patch.sh --status      # Show installed versions + ASAR fuse state
./patch.sh               # Interactive menu
```

`--install` is idempotent — re-running it removes any prior patched copy first, and the JS injection itself is guarded by a `CLAUDE RTL PATCH START` marker. There is no test suite, lint, or build step; the only artifact is the patched `.app` bundle.

Runtime deps (checked by `check_dependencies` in [patch.sh](patch.sh)): `npx` (Node ≥22.12, used to fetch `@electron/asar` and `@electron/fuses` on demand) and `codesign` (Xcode CLI tools). No `package.json` — npm tooling is invoked via `npx --yes` with the versions pinned in `ASAR_PKG` / `FUSES_PKG` at the top of the script. Bump those on purpose, never to "latest": the pin is there so an install does not run an unreviewed release.

## Patching pipeline (patch.sh)

The whole pipeline lives in [patch.sh](patch.sh) — a single bash script with `set -euo pipefail`. Steps in `install_patch`:

0. `verify_source_app`: `codesign --verify --deep --strict -R=<requirement>` on the source app. The requirement (`ANTHROPIC_REQUIREMENT`) demands an Apple-issued Developer ID certificate whose team is `EXPECTED_TEAM_ID`; comparing the `TeamIdentifier` string from `codesign -dv` would not tie the team to the certificate chain. The patched copy inherits the whole source bundle, so a tampered source must stop the install.
1. `cp -R` the source app to `~/Applications/Claude-RTL.app`, then run the same check on the copy before anything is modified (closes the gap between check and copy). A source that is a symbolic link is refused first, and `aliases_source_app` stops the install if the copy is a link or shares a file (`-ef`) with the original: BSD `cp -R` copies a link named on the command line as a link, and every later step would then write into the original.
2. Replace `Contents/Resources/electron.icns` with `icon.icns` and **delete** `CFBundleIconName` from `Info.plist` — macOS prefers the asset-catalog icon over the `.icns` file unless that key is removed ([patch.sh:384](patch.sh#L384)).
3. Set `CFBundleDisplayName=Claude-RTL`. Do **not** change `CFBundleName` — Electron's fuse lookup reads `CFBundleName` and changing it breaks the next step ([patch.sh:390](patch.sh#L390)).
4. `asar extract` → prepend a combined header (`rtl-payload.js` + an optional font injector built by `build_font_injector`) to the **window scripts** in `.vite/build/` → `asar pack`. Window scripts are the preload files the main process names by their `.vite/build/<name>.js` path (`mainView.js`, which is the claude.ai view for chat, Cowork and the Code tab, plus `mainWindow.js`, `quickWindow.js`, …); the script greps the build for those path strings rather than hardcoding names. The ~500 `index.chunk-*.js` files are main-process and worker code and are left alone. The **Electron main-process entry** (read from the extracted `package.json`'s `"main"` field, currently `index.pre.js`) is always skipped: injecting there makes Electron fail to spawn any `BrowserWindow` at startup (black-screen launch). The font injector runs unless the font is turned off: the default family is Vazirmatn (`DEFAULT_RTL_FONT`), `--font NAME` (or `RTL_FONT_FAMILY=NAME`) picks another, and `--font none` (or an empty `RTL_FONT_FAMILY`) skips it. Files named `index.js` / `index.*.js` are never targets, whatever path strings the build mentions. The injection is also skipped per-file if the `CLAUDE RTL PATCH START` marker is already present. Every current preload opens with a `"use strict";` directive; the script re-emits that directive in front of the header, because a directive that is no longer the first statement stops applying and Anthropic's code in that file would silently run in sloppy mode.
5. `@electron/fuses write … EnableEmbeddedAsarIntegrityValidation=off`. **Required** — Electron validates the ASAR hash at startup and the modified archive will crash the app without this.
6. Ad-hoc re-sign in three passes, all with `--options runtime`: (a) `--deep --preserve-metadata=entitlements` over the whole bundle, so every nested item keeps its own entitlements; (b) each `Contents/Frameworks/*.app` helper with the entitlements `write_entitlements` reads from the same helper in the original; (c) the app itself, last and without `--deep`, so its seal covers the re-signed helpers. Do **not** go back to one `--deep --entitlements` call: it stamps the main app's entitlements (camera, microphone, Apple Events, virtualization) onto the renderer and GPU helpers, which handle web content and have only `allow-jit` in the original. The original Anthropic signature is invalidated by the ASAR/fuse changes; ad-hoc signing is what lets macOS launch the modified bundle. `--options runtime` keeps the Hardened Runtime of the original (blocks `DYLD_*` injection and debugger attach). It needs one added entitlement on the app and its helpers, `com.apple.security.cs.disable-library-validation`: an ad-hoc signature has no team ID, so with library validation on they cannot load the Electron framework (`dyld: Library not loaded`, exit 134). Entitlements are extracted from the original and re-applied — without them, runtime entitlement checks fail (notably Cowork, which calls `@ant/claude-swift`'s VM check and shows "installation appears to be corrupted" when `com.apple.security.virtualization` is missing). Three team-id-coupled keys are stripped before re-signing: `com.apple.application-identifier`, `com.apple.developer.team-identifier`, `keychain-access-groups` — they reference Anthropic's team ID `Q6L2SF6YDW` and macOS rejects them under an ad-hoc signature.

`quit_claude_rtl` ([patch.sh:181](patch.sh#L181)) is deliberately scoped to the `Claude-RTL.app` bundle path so it never touches the user's running original Claude Desktop or Claude Code CLI.

## RTL payload (rtl-payload.js)

A self-contained IIFE wrapped in `// --- CLAUDE RTL PATCH START ---` / `--- END ---` markers (the start marker is what `patch.sh` greps for to skip already-patched files). Bails out early if `document` is undefined so it's safe to prepend to any script, including ones that may run in a non-DOM context. When editing payload behavior, preserve the start/end marker comments — removing them breaks idempotency.

Claude Desktop has native RTL handling: it sets `dir` from the **first strong character** of a block (on the `ul`/`ol`/`table` for lists and tables, and on an inline `span[dir]` wrapper inside table cells). The payload builds on that and overrides it with a **dominant-language rule** (`decide`): count words outside code/URLs/paths; ≥40% RTL → `rtl`, <30% → `ltr`, in between the first word decides, no RTL words → the block is never touched. Things to know before changing it:

- **`decide` must stay linear.** It runs on text the model or a web page controls, on every flush while a response streams. It reads at most `MAX_TEXT` characters, splits on whitespace and uses only plain scans per chunk (`isTechnical` once per chunk, not once per word). `textOf` copies at most `MAX_TEXT` characters and visits at most `MAX_NODES` nodes, so one huge text node or a block of empty elements costs no more. An earlier version stripped URLs and paths with unanchored regexes (`[\w.+-]+@…`) and took seconds on a long base64 string. Do not add a regex with a repeated class in front of a literal.
- **Owners.** Each RTL text node is mapped to the element that owns its direction (`ownerOf`): a prose block (`PROSE_SEL`), or else the nearest non-inline box. A box that is `flex`/`grid` with element children, or has block children, lays out other boxes and is never given a direction, so interface layout (a button with an icon, a sidebar row) is not mirrored; the text box inside it is marked instead. An `inline-block` that is the only child of its parent is treated as a text wrapper and passed through: the sidebar's session title is `span.dframe-fade-label (block, dir=auto, text-align:left) > span (inline-block) > span`, and the label is the box to mark. A box with no text of its own that holds the text wrapper next to another inline box (an `inline-block` button with an icon and a label) is not marked either: `arrangesBoxes` returns the wrapper, so the icon and the label keep their order. A marked box whose computed `text-align` is a fixed `left` (for RTL) gets `data-crtl-flip`, which moves it to the right; centred text is left alone.
- **Each list and table reads only its own part of the tree.** `partsOf` (lists), `table.rows` / `cells` / `tHead` (tables) and `innerOf` stop at a nested list, table or block; `collect` queues groups outermost first and `processList` takes a `done` set, so a nested list is handled once per run. Do not go back to `querySelectorAll` over a group's whole subtree: with deeply nested lists every level re-read everything below it. `textOf` checks the `contenteditable` attribute, not `isContentEditable`, which climbs every ancestor per node.
- **Groups.** A list or table gets one direction from all of its text. Its items/cells take that direction (markers and columns on one side); an item in the other language gets `data-crtl-text` (CSS `unicode-bidi: plaintext` + alignment to the group's side), so its text is ordered from its first strong letter. A nested list with no RTL text inherits the outer direction. A table whose header row is RTL is RTL regardless of its cells; the single-child box the app wraps a table in is marked too (`data-crtl-wrap`), so an RTL table starts at the right edge and scrolls from the right. Only lists drawn with markers count (`isProseGroup`); `ul`/`ol` with `list-style: none` are interface (sidebar, menus) and their items go through the interface-text path.
- **Attributes written:** `dir`, `data-crtl` (decided direction, with `!important` CSS behind it), `data-crtl-text`, `data-crtl-orig` (the app's own `dir`, restored by `unmark`), `data-crtl-in` (the app's inline `dir` wrapper, forced to follow its block), `data-crtl-wrap`, `data-crtl-flip`, `data-crtl-font`.
- **Never written to:** `pre`/`code`/math, monospace-styled boxes (diffs, tool output, a monospace list item or table cell), and anything inside a `contenteditable`. A marked element the app later moves into one of those is cleared by `recheck`. The prompt box is a ProseMirror editor; changing its DOM from outside fights its document model, so it only gets CSS (`unicode-bidi: plaintext` on paragraphs without a `dir`, and the font rule from `--font`). Plain `textarea` / text `input` elements do get `dir` and the font from `onInput`; they have no document model to fight.
- **The observer watches `childList` and `characterData`, not attributes**, so the payload's own writes cannot re-trigger it. Keep it that way.
- **No network, IPC, storage or `eval`.** The README's security section states this; keep it true.

The font family is not chosen here. `applyFont` only acts when `window.__claudeRtlFont` was set by `build_font_injector` (see below), so the family name has a single source of truth in `patch.sh`.

There is no test suite. To check a payload change, load `rtl-payload.js` with a `<script>` tag into a local HTML page that copies the structures above (a list with native `dir="ltr"`, a table cell with a `span[dir]` wrapper, a `white-space: pre-wrap` paragraph, a button with two text lines) and read the `data-crtl*` attributes back.

## RTL font (fonts/ + build_font_injector)

RTL letters get the bundled **Vazirmatn** font by default (`DEFAULT_RTL_FONT`); `--font NAME` (or `RTL_FONT_FAMILY=NAME`) picks another, and `--font none` (or an empty `RTL_FONT_FAMILY`) turns the font off. Latin text is never affected: every face is limited to RTL code points. The font's bytes are **embedded in the header as base64 and registered with the `FontFace` API** (`new FontFace(alias, arrayBuffer, …)` + `document.fonts.add`). Do not use an `@font-face` rule with a `data:` URI: claude.ai's CSP is `font-src 'self' assets.claude.ai … https://fonts.gstatic.com` with **no `data:`**, so a data URI is refused (`NetworkError`) and the text silently stays in the system font. A font built from bytes already in memory is not a fetch, so CSP does not apply; this was checked on claude.ai. `fonts.gstatic.com` is allowed by that CSP, but loading from it would make the app call Google on every start, so the bytes are embedded instead.

`build_font_injector` ([patch.sh](patch.sh)) is a no-op when `$RTL_FONT_FAMILY` is empty. When set, it auto-discovers every `*.woff2/*.woff/*.ttf/*.otf` in `fonts/`, keeps the ones whose file name is the family name followed by `.`, `-` or `[`, guesses weight/style from each filename (`-Bold`, `-Light`, `-Italic`, …; `Variable` or `wght` means a variable font, registered as `font-weight: 100 900`) and base64-encodes it into a `FontFace` registered under the fixed alias `$RTL_FONT_ALIAS` ("Claude RTL Font"). With no files it registers the alias from `local('<family>')` instead. Every face carries `unicodeRange: $RTL_UNICODE_RANGE`, so the font can only ever render RTL code points. The injector stores the alias in `window.__claudeRtlFont` and wraps everything in a guarded IIFE (`// --- CLAUDE RTL FONT START/END ---`) on the combined header.

The payload then prepends the alias to the **computed** font stack of each element that holds RTL text (`applyFont`, inline style). That keeps whatever font the element already had for Latin text (sans, serif, dyslexic) and leaves monospace elements alone. The inline value the element had before is kept in `fontPrev`; `collect` calls `dropFont` on every element it scans and re-applies the font only where RTL text still sits in a non-monospace font outside code, so a reused element that turns into tool output does not keep the old stack. Do not go back to a `[dir="rtl"] * { font-family: … !important }` rule: it replaced Latin glyphs too and flattened every font choice inside RTL blocks. Registering the faces under Claude's own family name (`anthropic-sans`) with a `unicode-range` was tried and does not work: faces with different weight descriptors are not merged, so Persian text fell back to the system font at weights without an exact match. The prompt box is the one place styled by selector (`.ProseMirror`), because the payload does not write into editors.

Bundled fonts: `Parastoo-Variable.woff2` (the Arabic-script subset Google Fonts serves, one variable file for weights 400–700, OFL — [fonts/OFL-Parastoo.txt](fonts/OFL-Parastoo.txt)) and Vazirmatn Regular/Bold (OFL — [fonts/OFL-Vazirmatn.txt](fonts/OFL-Vazirmatn.txt)).

Ways to choose (all without code edits):
- **Default:** `./patch.sh --install` — Vazirmatn.
- **CLI flag:** `./patch.sh --install --font Parastoo`, or `--font none` for no RTL font.
- **Different bundled font:** drop your own files in `fonts/` and pass `--font "<family-name>"` — embedded, so works even if not installed system-wide.
- **Installed font, no files:** `--font "B Nazanin"` with no matching files in `fonts/` uses an already-installed font of that name.
- **Env var alternative:** `RTL_FONT_FAMILY=Vazirmatn ./patch.sh --install` — equivalent to `--font`. The CLI flag overrides the env var when both are set.

Note: Parastoo and Vazirmatn cover Persian/Arabic but **not Hebrew** — Hebrew text falls through to the system Hebrew font. Hebrew users wanting a custom font should bundle one with Hebrew glyphs (Heebo, Rubik, Assistant, etc.) in `fonts/`.

The family name must match `[A-Za-z0-9 ._-]` or the script stops; it is written into JS (it only appears inside `local('…')`), and all generated CSS uses single quotes so it stays valid inside the double-quoted JS string literal.

## Security posture

The patched copy is weaker than the original by construction, and the README says so plainly: no ASAR integrity check, ad-hoc signature in a user-writable location, library validation off, no auto-update. Do not describe the patch as "safe" without those caveats. What the script controls, and must keep: source signature check, pinned npm tools, Hardened Runtime, smallest possible injection surface, no `sudo`, a payload with no network/IPC/storage/eval. `--status` warns when the copy's version is behind the original.

## Things that will trip you up

- **Don't patch `/Applications/Claude.app`.** That bundle is protected by macOS App Management (and root-owned on many machines, though not all: a drag-installed copy belongs to the user, so a stray write there succeeds and breaks its signature). Modifying it would also break Anthropic's auto-updates. Never run a command with that bundle as the working directory. The "copy to `~/Applications/`" design is the whole point.
- **Claude updates ≠ patched copy updates.** Anthropic's auto-updater only updates the original. After a Claude update the user must re-run `./patch.sh --install` to rebuild the patched copy from the new version.
- **`.vite/build/` is the injection target** — if Anthropic restructures the ASAR or stops naming preload files by their `.vite/build/<name>.js` path, the script dies with a clear error in `install_patch`. That's the first place to look when a new Claude version breaks the patch.
- **Claude's native RTL can change under the payload.** It is part of the claude.ai web app, which updates without an app release. If lists or tables look wrong after no local change, inspect where the app now puts `dir`.
- **Keychain re-auth is expected on first launch** of the patched copy. Different code signature ⇒ macOS asks the user to re-approve "Claude Safe Storage" access. Not a bug.
